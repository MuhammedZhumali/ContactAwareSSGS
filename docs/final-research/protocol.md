# Final research matrix: fixed 108 attempts

This protocol is written before final-series policy execution. The machine registration is `target/final-research/protocol.json`, generated by `scripts/register_final_research.py` only after the parent supplies the fully tested final JAR identity in `target/final-research/manifest.json`. The registration reads that manifest's explicit `identity`, `jar`, `jarSha256`, `sourcesFile` and `sourcesSha256`; it records the JAR, source-manifest, generator, this document and every model/audit hash. The matrix is fixed before results; this is one final compact evaluation, not a search for favorable cases.

Before the first experiment, final-v1 full-suite execution encountered five loopback-permission errors in `HttpImportTest` (478 tests, 473 passed, zero assertion failures). Its evidence is retained. The parent declared a new isolated final-v2 full-suite attempt with loopback access, without Java/source or matrix changes. Registration waits for a successful final JAR; it does not treat that environmental build retry as a policy retry or tune any case from policy outcomes.

## Question, hypotheses and common contract

We test whether a common bounded controller can benefit from additional contact visibility, and under which costs, loads, disruptions and computation delays that benefit disappears or reverses. No universal Multi advantage is assumed. X5 is a conditional short-return mechanism, Y is a null control, and the prior high-demand witness deliberately preserves unfavorable/incomplete history. The seed control tests whether DFS contributes beyond a cheap feasible plan; same-root candidate dominance does not imply better whole-mission execution.

Every matched Next/Multi comparison uses identical scenario bytes, allowed actions, costs, constraints, five-objective comparator, tie-break, search implementation, portfolio and budgets. Only horizon H changes. The objective is lexicographic: served contacts, useful secure time, then lower control CPU, management bytes and newly created directional keys. New keys are not key-pair counts. Next is H1; Multi is H2 except the one declared H3 sensitivity. Horizon is the program's visible future-contact parameter, including the current contact where applicable; no extra unobserved inputs enter the planner.

Practical search uses `SEED_AND_RETENTION`. The two diagnostic seed configurations use `SEED_WITHOUT_SEARCH`; this performs no DFS and is distinct from the `SEED_ONLY` variant that still searches. FixedPeriod uses activation-relative T=3600 s on mission workloads; PerContact uses JUST_IN_TIME preparation. Their legal executor actions and security assumptions are unchanged.

## Input identities and derivation

The frozen source families and historical evidence are listed in `docs/final-research/input-inventory.md`. Base model sources are `target/research-validation/models/ISS46.json`, `33591-base.json`, `20580-base.json`, `X5.json`, `Y.json`, `demand-none.json` and the five named security models. The generator validates their historical manifest hashes before copying. Unmodified models retain identical file bytes. Derived JSON uses exact Decimal numbers and integer nanoseconds; it never converts long counters or durations through floating point. `models/derivation-audit.json` records only explicitly permitted changed leaves, exact before/after values, source hashes and output hashes.

For full mission loads, rate=100 B/s, frame=1000 B, and minimum=1000 B in each direction for all levels. Low offers 1000 B/direction; medium offers 3000; high offers `max(3,floor(windowDurationNanoseconds/10000000000))*1000`. Thus each direction has a finite nonbinding high offer for the shared radio window, and low <= medium <= high even for short windows. Only offered-byte leaves change. Existing MODERATE is not used because it also raises the service minimum. Report complete delivered frames, offered demand and the payload-only service ceiling to distinguish demand saturation from security loss.

Base CP=5400 s, maximum material age=172800 s, reuse gap=86400 s and empty initial keys are common across the three mission families. All original selected contacts, station IDs and nanosecond window boundaries remain intact. The old X/Y fixture instead retains its own CP150, age400, gap200, 400 B/s, 100 B frames, 400 B/direction threshold and prior key history. The historical demand model keeps C1 offers39000 B/direction and C2/C3 offers1000, with its exact day2 geometry. Historical model labels/provenance strings stay unchanged; the derivation sidecar identifies the actual new workload.

Sensitivity changes exactly one factor relative to medium: either INSTALL phase durations x0.5/x2 with bytes fixed, or CP2700/10800. Duration scaling changes the assumed management transfer rate for INSTALL; it is a model sensitivity, not hardware calibration or uniform cost scaling. Other operations and bytes remain unchanged. H3 uses the unchanged medium model. Frozen evaluation profiles include the existing revocation-notice costs; no bare witness profile replaces them.

ISS geometry uses its saved 2026-10-10 day; NOAA/HST use their saved 2026-10-25 day. All have the frozen 32-station input, elevation10 degrees and guard0 selection. Public-orbit geometry is source-derived, while traffic, authorization, lifecycle limits, cryptographic costs and attacks remain synthetic. Different dates are not a simultaneous three-satellite operational demonstration. No fresh orbit acquisition, schedule regeneration, contact thinning, extra mission or outcome-based replacement is allowed within this series.

## Computation and stopping

The same registered budgets apply: 5000 nodes and 1000 ms per search, 2000 ms per decision, 350 ms each for seed and retained continuation stages, 10000 rollout transitions, 600 s external process watchdog, no cumulative controller wall-time limit, and one heavy JVM with 1024 MiB heap. Seed/retention work is within the common decision budget. The stage and transition limits are frozen implementation constants, not additional unreported allowances.

Offline computation does not advance scenario time. Measured mode uses fixed latency0, hostScale1 and the same 2000 ms modeled decision deadline. It measures this host's implemented observation/generation/selection path, not onboard hardware or a complete end-to-end command protocol. Checkpoint I/O and executor work have their existing timing treatment. Preserve reported actual delays, misses and fallback behavior.

A timeout, incomplete search or technical failure is retained with its exact stop reason, process log, available journal and checkpoint. Continue other independent registered cases; do not retry or increase budgets. An identity mismatch or failed evidence audit requires inspection before dependent work. Partial prefixes are diagnostic only, never substituted for final objectives or ranked as completed service losses. A completed search (`COMPLETE`), a controller reaching scenario end (`FINISHED`), served-contact count and deadline compliance are separate outcomes. FINISHED does not imply all contacts served or all searches complete. This series does not claim end-to-end optimality.

## Security and reporting boundary

The existing disclosure assumptions capture the active directional traffic-key pair at the external event. Recorded ciphertext is exposed under that pair; management/root material and replacements remain protected according to the saved model. Distinguish delivered, confidential and retrospectively decryptable bytes. Do not claim general compromise recovery or cryptographic security beyond these assumptions.

Recovery is reported in separate stages: spacecraft notice, independent replacement activation, independent SA opening and first independent delivered frame. Preserve censoring and absent events. A channel interruption can leave uncertainty or fail closed; without explicit reconciliation it is not evidence of restored peer consistency. Report actual interrupted management phases and partial consumed resources.

All completed, losing, tied, incomplete and technically failed cases belong in the final tables. Keep historical results version-separated and do not fill new missing cells with old outcomes. Report raw per-case metrics and versioned artifacts before any aggregate comparison. One deterministic execution per configuration is not a statistical sample and does not support population-level significance or universal policy superiority.

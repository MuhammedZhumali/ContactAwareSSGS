# Утверждение → свидетельства → ограничения

Все ссылки относятся к сохранённым данным; новые вычисления — только постобработка.
Для каждого тезиса ниже указаны контроль без атаки и зависимость от правила.

| Утверждение | Свидетельства | Ограничения |
| --- | --- | --- |
| Несколько контактов могут дать дополнительное обслуживание за счёт ранних операций | Автономный X/5, none: 3 против 2 обычных и конфиденциальных контактов при CAN и CW; INSTALL A перенесён в C1, при возврате INSTALLED | Пример существования в синтетической модели. Полезное время Multi меньше на 1 s, CPU больше на 0.71 s, management +1080 B, новых ключей +2. Не преимущество по всем целям |
| При достаточно длинном позднем окне наблюдаемый выигрыш может исчезнуть | X/9/CW: Next выполняет PREPARE перед C3, INSTALL/SWITCH/OPEN в C3 и успевает передать минимум; все пять случаев none/атак равны, включая conf-service | CAN при 9 s и оба правила при 3 s остаются незавершёнными. Ни универсальный минимальный порог, ни монотонность не доказаны |
| Поздние атаки X/5 не создают отдельного нового механизма выигрыша | None уже даёт 2/3 served; p70/p90/gap: 2/3 served и 1/2 confidential, оба правила; Multi использует новую независимую пару в C3 | C1 ретроспективно не набирает конфиденциальный минимум. CENSORED Next отражает также номинальную недоступность C3; нельзя представлять это как универсально быстрое восстановление |
| Original-атака X/5 меняет вывод и зависит от tie-break | Без атаки 2/3; после original обычных 3/3. CAN conf 2/3, bytes 9200/11400, первый независимый кадр 69.25/2.65 s. CW conf 2/2, bytes 9200/9200 и 69.25/69.25 s | Реакция вынуждает Next рано активировать новую пару, которая доживает до C3. Выигрыш CAN относится к независимым данным C1; его нельзя переносить на CW |
| Ранняя установка на ISS LIGHT даёт готовность без выигрыша обслуживания | SE2.4: все шесть завершённых пар равны по пяти целям и confidential service/bytes; none 3/3 conf, p90 2/2. CAN кадр в C3 на 4 s раньше также без атаки | CAN наблюдался на обоих днях; CW day2 равен, day1 неизвестен. После атаки ранняя g2 истекает, C3 обслуживает g3. Не доказана польза по дополнительным контактам на ISS |
| Спрос после уведомления делает независимую доставку наблюдаемой у Next | SE2.5: 2000 B в C1 после notice, три confidentialServedContacts при обоих правилах; без атаки также три. Проверка Claude 339/375 относится отдельно к старому SE2 и здесь не воспроизводилась |
| Одиночный COMPLETE не завершает контроллер | Сохранённый [лог Claude](../reviews/research-flow-audit-checks/logs/demand-multi-canonical.log): 1 061 822 узла, 63 s, корень Multi/CAN | Диагностика при другом временном режиме; нет полного исполнения, нового статуса или результата SE2.5. CW-incumbent также не является доказанным планом |

Пары C3=5 s используют смешанные исторические версии; `comparisons.csv` отмечает
различия commit, а проверка требует одинаковые физические входы. Это сравнения
сохранённых поведений, не новый единый benchmark. Целевая функция остаётся
«контакты → полезное время → CPU → bytes → новые ключи», с заданным tie-break.
Новая метрика не оптимизируется. Условная гипотеза об эффективности соответствует
этой постановке; рекомендации аудита о шестом критерии/смене бюджетов не применены.

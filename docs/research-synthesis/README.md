## Определение конфиденциального обслуживания

Для контакта c и направления d суммируются байты **полных фактически доставленных**
кадров, чей направленный keyId не входит в объединение KEY_DISCLOSED из журнала
до конца опыта. Результат `confidentialServed(c)` истинен тогда и только тогда,
когда обе суммы отдельно не меньше `minimumUplinkBytes` / `minimumDownlinkBytes`
исходного сценария. `confidentialServedContacts` — сумма этих индикаторов.
Раскрытие исключает как прошлые, так и последующие кадры соответствующего ключа;
отдельный чистый UL не компенсирует недостаточный DL. Смешанные поколения
допустимы, если каждый засчитанный направленный ключ остался нераскрытым.

Прерванный кадр, даже полностью излучённый, не является доставленным. Используется
прежний проверяющий `audit_security_evaluation.read_frame`; его физическая
проверка размера/длительности/байтов не копируется. Обычное обслуживание и
конфиденциальные байты дополнительно сверяются с прежним независимым аудитором
и сохранёнными метриками. Без фактического раскрытия обе оценки обслуживания равны.

Это ретроспективная оценка recording-attacker модели, не вероятность компрометации
и не новая информация для планировщика. Пять критериев остаются прежними.
Для любого статуса кроме FINISHED конечные поля пусты, `confidentialServiceStatus`
равен UNAVAILABLE. Наблюдённый префикс вынесен в journal-evidence.json: его чистые
байты ещё могут потерять конфиденциальность при последующем раскрытии. Он не
подменяет конечный результат. Этапы восстановления используют прежний контракт
SE2.1: EVENT / ALREADY-READY-AT-ORIGIN / CENSORED / NOT-APPLICABLE / UNAVAILABLE.

## Область и происхождение

- `runs.csv`: ровно 60 строк автономного X из SE2.3, 16 строк двух дней SE2.4,
  8 строк SE2.5. 20 C3=5 s — исторические версии SE2.2/SE2.2.1/SE2.2.2,
  повторно представленные в SE2.3, не дополнительные независимые эксперименты.
- `extra-attempts.csv`: три исходные CONTROLLER_TIME_LIMIT попытки SE2.3,
  оставленные отдельно от выбранных технических повторов. Они не удалены из доказательств.
- `contacts.csv`: раздельные пороги, обычные/конфиденциальные UL/DL и индикаторы
  каждого контакта; конечные поля незавершённых попыток пусты.
- `comparisons.csv`: 42 пары одного сценария и правила; только 21 завершённая
  пара имеет разности. Сравнение входов допускает различие имени и порядка Set,
  но не стоимости/начального состояния/нагрузки/атаки. Разные исторические
  бинарные версии отмечены `sameCommit=False`; их runtime не является общим benchmark.

Для каждой строки записаны источник summary, sourceCase/commit, путь модели и
журнала, SHA-256, статус, происхождение и выбранная попытка; пять прежних метрик,
новая метрика, конфиденциальные байты и четыре этапа восстановления стоят рядом.
Начальная история X содержит четыре ACTIVE-ключа, но не подготовленного кандидата
и не предписанного плана. Ранний X с общей подготовкой сюда не включён.

339/375 — отдельная сохранённая проверка Claude для атакованных FINISHED старого
SE2. Она не пересчитывалась и не переносится на эту выборку. Аналогично COMPLETE
одного корня за 63 s не меняет статусы полных исполнений SE2.5.

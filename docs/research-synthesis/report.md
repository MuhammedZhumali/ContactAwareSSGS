# ContactAwareSS: условия полезности прогноза

Сводка после SE2.5 и research-flow-audit. 24 октября 2026. Только сохранённые данные.

## 1. Основной результат и корректная метрика

**Подтверждён условный механизм, а не универсальное превосходство Multi.**
Знание нескольких будущих контактов позволяет раньше увидеть необходимость
обновления и перенести операции в предыдущее окно. В автономном X короткое окно
возврата после этого обслуживается; при более длинном окне Next может догнать
Multi. На выбранных ISS-фрагментах дополнительного обслуживания не показано.
Атаки проверяют последствия подготовки, а не задают основную цель исследования.

**Что считается обслуженным.** Прежний servedContacts сохранён. Рядом вычислен
confidentialServedContacts: по каждому контакту полные доставленные кадры на
направленных ключах, не раскрытых к концу опыта, отдельно должны покрыть минимумы
UL и DL исходного сценария. Раскрытие исключает также прошлые кадры этого ключа.
Прерванная передача не засчитывается. При отсутствии раскрытия обе оценки равны.
Это ретроспектива модели recording-attacker, не шестой критерий и не знание планировщика.

**Область.** 60 строк автономного X из SE2.3, 16 строк SE2.4, 8 строк SE2.5:
63 FINISHED, 20 SEARCH_INCOMPLETE, 1 CONTROLLER_TIME_LIMIT. Ещё три исходные
технические попытки SE2.3 сохранены отдельно. Двадцать строк X/C3=5 s исторические,
не новые независимые эксперименты. Ранний X с заданной общей подготовкой исключён.
Для незавершённых запусков все конечные показатели unavailable; prefix вынесен
отдельно. Проверены 87 журналов, 21 из 42 пар сопоставима и завершена.

| Случай; Next / Multi | Обычное обслуживание | Конфиденциальное обслуживание | Вывод |
| --- | --- | --- | --- |
| X/5, none, оба правила | 2 / 3 | 2 / 3 | Дополнительный контакт уже без атаки |
| X/5, p70/p90/gap, оба | 2 / 3 | 1 / 2 | Выигрыш C3 сохраняется; C1 раскрыт |
| X/5, original, CAN | 3 / 3 | 2 / 3 | Выигрыш конфиденциальной доставки C1 |
| X/5, original, CW | 3 / 3 | 2 / 2 | Выигрыша нет |
| X/9, CW, none / атаки | 3 / 3 | 3 / 3; при атаке 2 / 2 | Равенство пяти целей и recovery |
| ISS SE2.4, 6 завершённых пар | 3 / 3 | none 3 / 3; p90 2 / 2 | Только готовность при CAN |
| ISS SE2.5, оба правила | Next 3; Multi unavailable | Next 3; Multi unavailable | Эффект горизонта неизвестен |

CAN = CANONICAL, CW = CONTINUE_WAIT; оба применяются одинаково к Next и Multi.
В 42 из 63 выбранных FINISHED обычный и конфиденциальный счёт различаются.
Это характеристика данной выборки. Число Claude «339 из 375» относится отдельно
к старому SE2; оно не переносится сюда. Источники каждой строки, пять целей,
байты и четыре этапа восстановления приведены в runs.csv; все 42 пары — в comparisons.csv.

## 2. Когда перенос операций помогает

| Сценарий | Раньше видит | Переносит | Перед возвратом | Результат | Tie-break |
| --- | --- | --- | --- | --- | --- |
| X/5, none | Возврат A после expiry | PREPARE + INSTALL в C1 | Multi установлен; Next без пары | +1 контакт | Оба |
| X/9, CW | Та же необходимость | Ранний INSTALL не нужен | Оба подготовлены | Next успевает в C3 | Только CW завершён |
| ISS LIGHT | Возврат A после CP5400 | CAN: INSTALL g2; после атаки также g3 | Multi установлен; Next подготовлен | Раньше готов, объём тот же | CAN; CW day2 равен |
| ISS, спрос C1 | Multi остановлен в AOS | Не установлено полным запуском | Не наблюдалось у Multi | Next: 2000 чистых B после notice | Для Multi неизвестно |

**Автономный X/5 без атаки.** C1=0…20, C2=30…50, C3=80…85 s. Старый A истекает
в t=70. Multi видит C3 внутри C1, Next тогда видит только C1/C2. Подтверждённый
INSTALL A нельзя выполнить в C2 со станцией B. CAN завершает PREPARE в t=3,
INSTALL в 7; CW — в 15.75 и 19.75. Подготовленный материал допустим до 403/415.75,
поэтому выдерживает разрыв. В C3 SWITCH 80…81 активирует пару до t=231,
OPEN 81…82 открывает SA, восемь кадров по 100 B/0.25 s достигают минимума
400 B UL + 400 B DL в t=84. Все ресурсы и подтверждения соблюдены.

Next не создаёт запас в номинальном X/5. Даже для уже PREPARED пары цепочка
INSTALL 4 s + SWITCH 1 s + OPEN 1 s заняла бы 6 s до данных, больше C3.
Ранний перенос у Multi стоит +0.71 s CPU, +1080 B и +2 ключа; useful time
37 против 38 s. Дополнительный контакт перевешивает это по первому критерию.
Это фактические допустимые цепочки, не доказанный глобальный минимум времени.

**X/9/CW.** Обе политики PREPARE в 78…80, затем INSTALL до 84, SWITCH до 85,
OPEN до 86; минимум кадров достигнут в 88 < 89. При p90/gap сначала требуется
уведомление КА 80…80.4, и минимум достигнут в 88.4. Для original пара уже активна
в 19.4 и допустима до 169.4. По всем пяти случаям получено равенство.
Оба Multi при 3 s и CAN при 9 s незавершены; универсальный порог не определён.

**ISS LIGHT.** Здесь кадр 1000 B занимает 10 s, минимум UL+DL требует 20 s.
Фактическая цепочка Next из PREPARED: 4+1+1+20=26 s; Multi из INSTALLED:
1+1+20=22 s. Окна возврата 405.994262695/121.556396484 s вмещают обе цепочки,
дальнейший offered-спрос исчерпан. Порог X «8–10 s» сюда неприменим. При CAN
первый кадр возврата появляется через 12 вместо 16 s **также без атаки**.
Day2/CW готовность и доставка равны; day1/CW Multi незавершён.

Подробные ключи, сроки, ресурсы и последовательности: mechanisms.md и фактические
events/returnEntry в target/research-synthesis/mechanisms.json. Состояния и минимумы
нельзя заменять одной суммой длительностей, общей для X и ISS.

## 3. Атаки, ограничения и граница вывода

**X/5.** Поздние p70/p90/gap сохраняют номинальный выигрыш C3 при обоих правилах;
Next не обслуживал C3 и без атаки. После original аварийная реакция, наоборот,
заставляет Next рано обновить A: обычных контактов становится 3. При CAN у Multi
уже есть установленная пара: независимый кадр через 2.65 против 69.25 s,
конфиденциальные байты 11400 против 9200, конфиденциальных контактов 3 против 2.
При CW обе политики дают 69.25 s, 9200 B и 2 конфиденциальных контакта.
Следовательно, быстрый original-recovery зависит от правила.

**ISS SE2.4.** После p90 CAN Multi активирует g2 через 1.4 s, Next через 7.4 s
от ground notice. Но спрос C1 уже исчерпан, а g2 истекает до C3. На day2 сроки
g2 — 01:44:25.120977783 / 01:44:31.120977783; возврат в 01:47:18.202056885 UTC.
Доставляет уже g3: Multi устанавливает её в C1, Next в C3. Ранняя активация g2
не означает непрерывную готовность. У обеих политик при атаке 4000 чистых B и
2 конфиденциальных контакта; без атаки 6000 B и 3. Это не преимущество обслуживания.

**SE2.5.** У Next после notice остаётся спрос, и при обоих правилах два независимых
кадра в C1 дают 2000 B и сохраняют все три конфиденциально обслуженных контакта.
CAN/CW: первый кадр через 18.4/21.975317383 s. Разницу создаёт уже начатый DL,
который задерживает уведомление КА. Меньшее суммарное раскрытие само по себе не
означает более быстрое восстановление: объём и фаза передачи различаются.
Все четыре Multi остались SEARCH_INCOMPLETE; качества их полного исполнения нет.

| Утверждение | Свидетельства | Ограничения |
| --- | --- | --- |
| Горизонт может добавить контакт | X/5 none: 2→3 при CAN и CW; ранний INSTALL | Синтетический пример существования; расход больше |
| Длинное окно может убрать выигрыш | X/9/CW: равенство всех пяти случаев | CAN/9 и Multi/3 неизвестны; не универсальная граница |
| Быстрая готовность не равна обслуживанию | ISS: 1.4/7.4 s активация, равные итоговые объёмы | g2 истекает; C3 на g3; эффект зависит от tie-break |
| Остаточный спрос полезен для Next | SE2.5: +2000 независимых B в C1 относительно LIGHT | Нет завершённого Multi, сравнение горизонтов отсутствует |
| Один COMPLETE не завершает опыт | Сохранённый корень Claude: 1 061 822 узла, 63 s | Диагностика, иной временной режим; статусы SE2.5 прежние |

**Достоверность и пределы.** Восемь целевых тестов и независимый аудит обычного
учёта/конфиденциальных байтов прошли. Сохранены 3923 прежних файла; Java, политики,
comparator, guard, бюджеты и пять приоритетов неизменны. Новых симуляций и Maven
нет. Затраты синтетические; прогноз конечный, модель дискретна; вычисления не
расходуют время контактов. Смешанные версии X/5 отмечены, не образуют нового
benchmark. Два tie-break и целевые фрагменты не доказывают общую устойчивость.

# SE2.2: контрольная точка X до ISS/Y

Сохранена до расширения серии. Машинная проверка: [x-intermediate.json](x-intermediate.json).
Неизменяемая копия таблиц: `target/security-evaluation-se22/x-intermediate/`.

20 зарегистрированных попыток: 10 FINISHED, 5 SEARCH_INCOMPLETE, 5 PROCESS_ERROR.
Все завершённые CANONICAL совпали с SE2 по событиям и итоговым метрикам.
Все доступные полные и частичные журналы прошли независимый учёт затрат,
кадров, ключей и счётчиков. PASS относится к проверке доступных свидетельств,
а не к завершению всех сравнений.

Восстановлены два фактических состояния без повторного поиска прошлого:

| Состояние | H | Оптимальная пятёрка относительно корня | Все оптимальные первые действия |
|---|---:|---|---|
| t=1, перед PREPARE | 1 | (2, 38 s, 0.06 s, 80 B, 0) | CONTINUE |
| t=1, перед PREPARE | 2 | (3, 37 s, 0.77 s, 1160 B, 2) | PREPARE A; CONTINUE |
| t=3, перед INSTALL | 1 | (1, 36 s, 0.06 s, 80 B, 0) | CONTINUE |
| t=3, перед INSTALL | 2 | (2, 35 s, 0.57 s, 1160 B, 0) | INSTALL A; CONTINUE |

Каждый кандидат отдельно доведён до границы горизонта под CANONICAL;
эти четыре множества полны. Пятёрка и допустимость продолжений не зависят
от разрешения равенства. Под CONTINUE_WAIT повторная проверка t=1/H2
незавершена, остальные три полны; в t=3/H2 выбран CONTINUE вместо INSTALL.
Это подтверждает механизм выбора момента установки, но не тождество
дальнейших полных исполнений контроллера.

Оригинальные программы Claude сохранены и повторены. Его адаптированный
вызов полного X original возвращает время первого независимого кадра
69.25/2.65 s для Next/Multi canonical и 69.25/69.25 s для lazy.
Его диагностический алгоритм проверяет альтернативы через канонический
поиск продолжений; это отдельное свидетельство, а не подмена новых запусков.
Его обработка ненулевой INCOMPLETE-оценки ограничивает доказательность.

Новый интегрированный CONTINUE_WAIT Multi во всех пяти X-попытках
останавливается на поиске в t=0 по TIME_LIMIT=30 s. Его полные результаты
не получены. Пять других попыток прерваны Windows AccessDeniedException
при атомарном переименовании checkpoint; причина файловой блокировки
не установлена. Последние записанные checkpoint и логи сохранены.

Несогласия завершённых эталонов не обнаружено. Ограниченная заранее
записанная ISS/Y серия продолжается с тем же JAR и бюджетами; повторов,
повышения лимитов и исправления исполнителя внутри серии нет.

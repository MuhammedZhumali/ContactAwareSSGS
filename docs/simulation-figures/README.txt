CONTACTAWARESS: FIGURES FOR THE SYNTHETIC C1/C2/C3 WITNESS

Назначение
Четыре рисунка на английском для статьи, построенные по фактическому журналу Java
SimulationEngine. Сравниваются заранее заданные планы Next-contact-aware и
Multi-contact. Автоматические политики и оптимизатор пока не реализованы.
Это синтетический пример с модельными затратами, не измерения на ISS.

Файлы
figures/01_outcomes.*       Обслуженные контакты, полезное время, CPU и байты.
figures/02_timeline.*       Исполненные операции и полезная передача по времени.
figures/03_cost_breakdown.* CPU земли/КА, uplink/downlink, радио и elapsed time.
figures/04_cumulative.*     Накопленное обслуживание и полезное время.

У каждого рисунка есть векторный PDF, SVG с редактируемым текстом и PNG 600 dpi.
Ширина рисунка 7.16 дюйма, рассчитана на две колонки IEEE.
Для статьи предпочтителен PDF; для Word/слайдов подходит PNG.
При использовании SVG в другом редакторе проверьте наличие шрифта DejaVu Sans.
Цвета планов дополнены штриховкой/стилем линий там, где это помогает сравнению.

data/metrics.csv           Итоговые результаты с единицами в именах столбцов.
data/contacts.csv          Обслуживание, время, байты и кадры каждого контакта.
data/operations.csv        Начало/конец и фактические затраты каждого шага.
                          Все длительности/CPU/radio в секундах; трафик в байтах.
source/*.json              Неизменённые исходные результаты Java, включая события.
manifest.json              SHA-256 источников, версии библиотек и результаты сверки.
quality-check.json         Проверка форматов, встроенных шрифтов и повторяемости.
captions.txt               Готовые английские подписи.
latex/figures.tex          Четыре figure* с подписями.
latex/results_table.tex    Компактная таблица результатов.

Как вставить в Overleaf
1. Загрузить папку simulation-figures из ZIP в корень проекта.
2. В преамбуле: \usepackage{graphicx}
3. В тексте: \input{simulation-figures/latex/figures.tex}
4. Для таблицы: \input{simulation-figures/latex/results_table.tex}
Можно взять только нужные figure* из файла. Для другой структуры каталогов задайте
\newcommand{\securityfigdir}{путь/к/figures} до подключения figures.tex.
Готовые рисунки не заменяют существующие разделы статьи автоматически.

Проверка выпуска
Все четыре PDF отрендерены через Poppler и визуально проверены.
Проверены встроенные шрифты, отсутствие растровых изображений внутри PDF,
редактируемый текст SVG, PNG 600 dpi и совпадение SHA-256 исходных журналов.
Повторная генерация дала побайтово одинаковые 12 файлов рисунков, CSV и LaTeX.
Намеренная замена общей CPU в X/Next с 0.32 на 0.33 была обнаружена до построения.

Как воспроизвести из корня ContactAwareSS
1. Собрать Java-проект по README и выполнить:
   java -cp target/contact-aware-contacts.jar org.contactaware.security.simulation.WitnessSimulationMain target/figure-input-new
   Каталог результата Java должен быть новым или пустым.
2. Используя Python 3.12, установить локальные зависимости:
   python -m pip install --target .tools/figure-python -r scripts/requirements-figures.txt
3. Построить:
   python scripts/plot_security_simulation.py --input target/figure-input-new
   Скрипт проверяет журнал, metrics, summary и formal-cost-model-and-horizon/verification.json
   до построения. --output позволяет выбрать другой каталог.
4. Для построения только из сохранённого снимка:
   python scripts/plot_security_simulation.py --input docs/simulation-figures/source --output target/figure-reproduction
Исходный код построения и независимый verification.json находятся в репозитории.
ZIP для Overleaf содержит рисунки, таблицы, подписи и исходные журналы; это не
самостоятельная поставка Java-проекта и среды Python.

Интерпретация
X = A [0,20), B [30,50), A [80,85).
Next: 19 + 19 + 0 = 38 s, 2 контакта, 0.32 CPU-s, 160 служебных байт.
Multi: 14 + 19 + 4 = 37 s, 3 контакта, 0.83 CPU-s, 1240 служебных байт.
Y = A [0,20), B [30,50), B [80,85).
Оба плана: 19 + 19 + 4 = 42 s, 3 контакта, 0.38 CPU-s, 240 служебных байт.

В каждом случае включена общая PREPARE [-2,0]: 0.20 CPU-s земли и 2 новых ключа,
даже если эти ключи не используются. Создание старых ключей до начала опыта,
CPU шифрования payload и CPU поиска решения не учитываются.

На временной диаграмме все разрывы соответствуют реальной линейной шкале времени;
показаны объединённые последовательности завершённых кадров. Ширина управления
равна elapsed time, а не времени занятости радио. Нулевые STOP/EXPIRE не занимают
интервалы. Old A deadline берётся из события истечения в X/Next.

На накопленном графике обслуженный контакт засчитывается при его завершении,
а не при первом достижении минимального объёма. Полезное время засчитывается
при завершении каждого кадра. Эта конвенция не меняет итоговое число контактов.

Границы выводов
Multi получает преимущество по числу обслуженных контактов в X, но требует больше
CPU и трафика и даёт на одну секунду меньше суммарного полезного времени.
Показанная ранняя активация не является единственной стратегией с таким результатом:
проверенный ранее install-now / activate-later вариант здесь не изображён.
Четыре исполнения детерминированы, поэтому доверительные интервалы не добавлены.
Рисунки не доказывают глобальную оптимальность, безопасность при компрометации,
общее превосходство алгоритма или результат сравнения на 46 контактах ISS.

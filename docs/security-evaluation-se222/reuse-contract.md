# Контракт интеграции reuse

Опция `SecurityPolicyController(..., boolean continuationReuse)` выключена по
умолчанию; Next/Multi имеют один путь исполнения. `RecedingHorizonController`
предоставляет такой же opt-in. Политики правил не получают доказательства поиска.

Исходный сертификат создаётся приватным конструктором внутри final
`ExactHorizonPlanner.selectUnrestricted`: он связывает конкретный неограниченный
вызов с наблюдением, объектом результата и правилами. Контроллер проверяет эту
связь. Адаптер, который лишь передаёт rules или вызывает planWithFirstAction,
сертификата не получает. Guard-only API SearchEvidence сохраняется для прежних
проверок, но производственный путь не выводит provenance из одного статуса COMPLETE.

`ProvenContinuation` имеет закрытый конструктор. Корень содержит исходный
SearchEvidence и ссылку decision:N. Только успешный `Assessment.derive()` создаёт
следующий элемент с parent, новым наблюдением и offset+1. Производные элементы
не создают HorizonPlanResult и не выдаются за новый завершённый поиск. По индукции
каждый элемент использует условное обоснование из ../continue-suffix-check.md;
несколько CONTINUE допустимы только через отдельный ALLOWED на каждом шаге.

Контроллер сначала обрабатывает обычное новое наблюдение и обязательную реакцию
на известный инцидент. Затем проверяет остаток; отказ/неподдерживаемый случай
приводит к свежему поиску. После любого выбора исполняется одно действие.
INCOMPLETE не исполняет incumbent. После не-CONTINUE guard консервативно отказывает,
после смены контакта/горизонта или незавершённого кадра доказательство также теряется.
Происхождение и отказ видны в ContinuationAudit. Реестр proof живёт только в run;
глобального кэша и сериализации цепочки в checkpoint нет.

Проверка и создание следующего proof выполняются внутри общего SearchControl.
Guard/preparation/selection имеют отдельные elapsed-счётчики; фактический поиск
сохраняет собственную телеметрию. Все прочие затраты, включая запись checkpoint,
входят в общий elapsed контроллера. Системный вызов не обязан прерываться мгновенно;
отдельный watchdog остаётся последней границей. Модельное время не расходуется поиском.

Независимое чтение ограниченных файлов выявило две проблемы до эксперимента:
недостаточную provenance при доверии произвольному адаптеру и два чтения nanoTime
для одной длительности подготовки. Обе исправлены. Повторное чтение подтвердило
приватный сертификат, проверку identity результата и единый замер длительности.
Подагент не выполнял тестов; валидацией и запуском JVM управлял основной агент.
